# Подключение MAX к Hermes Agent

Это инструкция для текущего внешнего плагина. Плагин не обещает универсальную
доступность MAX при любых региональных ограничениях связи: результат зависит
от региона, оператора, устройства и режима ограничения.

## 1. Создание бота

Используйте актуальный процесс MAX для бизнеса и получите Bot API token.
Старые инструкции про `@MasterBot` и `/newbot` намеренно не используются:
правила регистрации и верификации MAX менялись.

Официальные страницы:

- https://dev.max.ru/docs/chatbots/bots-coding/prepare
- https://dev.max.ru/docs-api

## 2. Установка без изменения Hermes core

Репозиторий плагина должен оставаться отдельным от Hermes:

```bash
python -m pip install -e ".[dev]"
ln -s "/path/to/hermes-agent-max-vk/plugins/max" "$HOME/.hermes/plugins/max"
```

В Windows вместо `ln -s` используйте junction или каталог-копию. Внутри
установленного каталога должен быть файл `plugin.yaml` в нижнем регистре.
Файлы Hermes `gateway/`, `agent/` и `hermes_cli/` изменять не нужно.

## 3. Минимальная конфигурация

```env
MAX_BOT_TOKEN=<token MAX для бизнеса>
MAX_ALLOWED_USERS=<числовые user_id через запятую>
# Для групп нужны одновременно разрешённые пользователи и чаты.
MAX_GROUP_ALLOWED_USERS=<user_id через запятую>
MAX_GROUP_ALLOWED_CHATS=<chat_id через запятую>
MAX_ADMIN_USERS=<администраторы групп через запятую>
# Необязательно: максимум 50 000 000 байт на одно вложение (предел плагина).
MAX_MEDIA_MAX_BYTES=50000000
```

Для изображений дополнительно проверяется длина каждой стороны: не более 7680
пикселей. Плагин использует Pillow для чтения заголовка изображения; пиксели не
декодируются целиком при проверке размера. Для HEIC устанавливается
`pillow-heif`; обе библиотеки входят в зависимости проекта.

Если `MAX_WEBHOOK_URL` не задан, используется Long Polling. MAX ограничивает
его по скорости и сроку хранения событий и не рекомендует для постоянной
эксплуатации. Для production MAX рекомендует Webhook: [документация обновлений](https://dev.max.ru/docs-api/methods/GET/updates).

## 4. TLS и сертификаты

Актуальный API: `https://platform-api2.max.ru`.

Если в системном хранилище нет нужной цепочки, задайте путь к проверенному PEM
bundle:

```env
MAX_CA_BUNDLE=/etc/hermes/max-ca-bundle.pem
```

Плагин сохраняет системные корни ОС и добавляет сертификаты из указанного
bundle. Поэтому bundle может содержать только актуальную доверенную цепочку
MAX; нельзя исправлять проблему через `verify=False`.

## 5. Webhook

```env
MAX_WEBHOOK_URL=https://example.com/hermes/max
MAX_WEBHOOK_SECRET=<5-256 символов: латиница, цифры, _ или ->
```

MAX требует публичный HTTPS на порту 443, доверенный сертификат и HTTP 200 не
позднее 30 секунд. Плагин проверяет адрес перед подпиской, а `MAX_WEBHOOK_URL`
переключает MAX-адаптер на Webhook; Long Polling параллельно не запускается.
При старте адаптера сразу запрашивается подписка MAX; доступность публичного
ingress, DNS, TLS и reverse proxy автоматически не проверяется. Сначала
запустите и проверьте ingress и общий SQLite-файл, затем задайте
`MAX_WEBHOOK_URL` и переключайте транспорт в согласованное окно.

`MaxAdapter.handle_webhook()` проверяет заголовок
`X-Max-Bot-Api-Secret` и записывает событие в SQLite до подтверждения MAX.
Входной ASGI процесс запускается отдельно от Hermes:

```powershell
python -m pip install -e ".[webhook]"
python scripts/max_webhook_server.py
```

`MAX_INBOX_PATH` должен указывать на один и тот же SQLite-файл у ingress и
Hermes. Сервер по умолчанию слушает `127.0.0.1:8080`; reverse proxy принимает
публичный HTTPS/443 и передаёт запросы на него. Не указывайте `MAX_WEBHOOK_URL`,
пока не проверены домен, TLS, ingress и восстановление SQLite: иначе адаптер
переключится с polling на Webhook, но MAX не сможет доставить события.
Подробности: `docs/ops/max-upgrade-safe.md` и `docs/ops/max-certificates.md`.

## 6. Политика доступа

Для пилота Webhook с автоматическим возвратом к прямому polling предусмотрен
[отдельный регламент](../ops/max-webhook-failover.md). Резерв включается явно,
не требует рестарта всего Hermes при отказе и не гарантирует голосовые в polling.
Не включайте его до проверки общего inbox, HTTPS и отката.
С версии 0.2.4 отдельно включается автоматический возврат из резерва в Webhook:
`webhook_auto_return: true`. Порядок проверок, выдержка и поведение при
неопределённой подписке описаны в [регламенте автовозврата](../ops/max-auto-return.md).

По умолчанию доступ закрыт:

- `MAX_ALLOWED_USERS` — разрешённые DM и группы;
- `MAX_GROUP_ALLOWED_USERS` — пользователи только для групп;
- `MAX_GROUP_ALLOWED_CHATS` — разрешённые group chat ID;
- `MAX_ADMIN_USERS` — пользователи, которым разрешены approval и управляющие
  действия в группах;
- `MAX_ALLOW_ALL_USERS=true` — только временная разработческая настройка.

Доступ в группе проверяется как логическое «И»: отправитель должен быть в
пользовательском allowlist, а чат — в `MAX_GROUP_ALLOWED_CHATS`. В группах
контекст Hermes разделяется по паре `chat_id + user_id`; физическая доставка
при этом возвращается в исходный MAX chat ID. Обращением к боту считается
упоминание, команда или ответ именно на сообщение бота; ответ другому участнику
или пересылка сами по себе обращение не создают.

Важно: текущий глобальный Hermes registry сначала применяет
`MAX_ALLOWED_USERS`. Поэтому пользователи, которым разрешён доступ только в
группе, всё равно должны присутствовать в глобальном allowlist; групповые
переменные дополнительно сужают решение внутри MAX-плагина, а не обходят
глобальную проверку Hermes.

Не включайте `MAX_ALLOW_ALL_USERS` для публичного бота.

Списки ID в YAML задавайте списками, например `allow_admin_from: []` или
`allow_from: ["12345678"]`. В переменных окружения используйте ID через запятую.
Пустой список администраторов не включает ограниченный режим команд. Если
список администраторов задан непустым, остальным разрешены только команды из
`user_allowed_commands` / `group_user_allowed_commands` и базовая справка.
Намеренно запрещённая команда получает понятный ответ и состояние `failed`
в очереди, а не молча считается выполненной. Доступ неизвестным отправителям
по-прежнему закрыт до обработки команды.

Несколько ботов могут обслуживаться одним профилем Hermes, если каждый имеет
свой platform key, учётные данные и SQLite-состояние. Нельзя запускать двух
получателей `/updates` для одного и того же токена. Настройки дочернего профиля
не должны записываться в общее окружение родительского процесса; адаптер читает
свои разрешения, токен и пути через активную область настроек Hermes.

## 7. Что сейчас реализовано

- текстовые DM и закрытые group routing с раздельными сессиями участников;
- нормализация `body.mid` и `recipient.chat_type`;
- chunking до 4000 символов;
- `Authorization` и API v2;
- Long Polling с marker;
- Webhook secret, ACK decision, bounded queue и dedup;
- Hermes plugin contract, YAML hook и standalone sender;
- входящие image/audio/video/file через локальный Hermes media cache, включая
  разрешение video-token через `GET /videos/{token}`;
- исходящие изображения, документы, audio/voice, video, animation, `MEDIA:` и
  standalone/cron через общий `/uploads` → multipart `data` → message поток;
- несколько вложений, кириллические имена и `[[as_document]]`; изображения и
  видео группируются до 12 вложений, файлы и аудио отправляются отдельными
  совместимыми сообщениями; ошибка одного вложения не скрывает остальные, а
  MAX отдельно сообщает номера недоставленных изображений или число ошибок;
- меню до 32 подтверждённых Hermes-команд через `PATCH /me/commands`, `/menu`,
  `/start`, `/commands`, `/maxstatus` и inline-кнопки; список команд также
  дублируется текстом, если клиент MAX не показывает системное меню;
- индикатор `typing_on` с обновлением штатным циклом Hermes, durable inbox для обоих транспортов и состояния
  `pending`, `dispatching`, `accepted`, `processing`, `processed`, `failed` и
  `unknown`; после перезапуска событие в полёте становится `unknown` и не
  запускается повторно;
- отдельный приоритетный обработчик команд и callbacks, два параллельных
  обработчика обычных событий, не более двух одновременных загрузок; polling
  продолжает принимать обновления, пока загружается вложение;
- отдельные SQLite inbox и callback-идентификаторы, чтобы разные нажатия на
  одну клавиатуру не считались одним событием;
- ограничение размера и проверка официальных HTTPS media-hosts;
- предел 50 000 000 байт на файл и 7680 пикселей на сторону изображения; при
  явно распознанном неподдерживаемом аудиоформате исходный файл отправляется как
  документ с пояснением;
- безопасная TLS-политика.

### Индикатор «печатает»

С версии 0.2.5 для личного диалога отправка ответа и индикация используют разные адреса:
ответ — `user_id`, действие `typing_on` — внутренний `recipient.chat_id` из
входящего события. Плагин запоминает эту связь при начале разрешённой задачи
в памяти конкретного адаптера. Идентификаторы сессий и адресация ответов сохраняются.
Для группы используется ID группы, без суффикса сессии участника.

Индикатор обновляется штатным циклом Hermes во время обработки. Для отключения
используется параметр `typing_indicator: false` в настройках платформы MAX.
После завершения или отмены обновления прекращаются; время исчезновения
индикатора определяется MAX и клиентом. Недокументированный `typing_off` не
отправляется. Если внутренний ID диалога отсутствует, действие пропускается:
подставлять вместо него ID пользователя нельзя.

[Документация MAX](https://dev.max.ru/docs-api/methods/POST/chats/-chatId-/actions)
описывает этот endpoint как действие в групповом чате. Показ в личном диалоге
нужно отдельно подтвердить на используемой версии приложения; успешные
локальные тесты сами по себе не подтверждают отображение на телефоне.

### Голос, музыка и видео

В MAX запись голоса поступает как вложение `audio`. Начиная с MAX 0.2.2
такие вложения направляются в штатный голосовой обработчик Hermes (`VOICE`):
`AUDIO` в новых версиях Hermes означает файл и не запускает автоматический
STT. Это правило распространяется и на обычное аудиовложение MAX: API не
даёт надёжного отдельного признака записи голоса. Если нужна передача
музыки или аудио без распознавания, отправьте её как файл (`file`).
Доступность распознавания зависит от уже настроенного STT Hermes; плагин
не устанавливает движок и не выбирает облачного провайдера автоматически.

Исходящий голос передаётся воспроизводимым аудиовложением. Это не гарантия
Telegram-подобного голосового пузыря. MAX может перекодировать аудио и
изображение; `[[as_document]]` сохраняет исходные байты при отправке файлом.
Видео принимается по прямой ссылке или через `GET /videos/{token}`;
миниатюра и потоковый плейлист не подменяют видеофайл. Передача видео не
означает, что выбранная модель понимает его содержание.

В polling-пути нативный голос и видеокружки из некоторых актуальных клиентов
MAX приходят неполными: возможен `message_created` без самого сообщения либо
пустая пересылка без медиа. Этот случай описан в
[issue официального SDK №250](https://github.com/max-messenger/max-bot-api-client-ts/issues/250).
Исправление обработки неполных событий в SDK не восстанавливает отсутствующий
звук или видео. Если известен разрешённый отправитель, плагин отвечает на
пустое сообщение просьбой отправить обычный файл. Если MAX не передал даже
отправителя, плагин фиксирует `incomplete_update`, но не угадывает, кому писать.
Пересылка обрабатывается, когда API действительно передал её содержимое;
внешний отправитель и ID пересылки сохраняются, исходный автор не получает
его разрешения. Один лишь чужой `mid` не даёт доступа к записи.

Есть [сообщение участника от 9 октября](https://github.com/max-messenger/max-bot-api-client-ts/issues/250#issuecomment-6076292698)
об успешном прямом голосе через **Webhook** при пустом polling-событии.
Кружки он не проверял, пересланный голос оставался недоступен. Это основание
для контролируемого пилота, а не гарантия исправления всех вложений.
Подробные условия, разбор готовых решений и отдельная матрица прямого голоса,
кружка и их пересылок: [исследование входящих записей](../project-status.md).
Не подключайте подписку к рабочему боту до готовности HTTPS-входа.

Для обновления исходящего Edge TTS без изменения ядра предусмотрена
[отдельная настройка командного провайдера](edge-tts-command.md).
Она необязательна и может затронуть Telegram того же профиля; требуется
согласие владельца. Это не обход отсутствующих входящих медиа MAX.

### Ограничения размера и длительности

| Тип | Наш канал | Официальный предел MAX Bot API |
| --- | --- | --- |
| Изображение | 50 000 000 байт; каждая сторона до 7680 px | 50 МБ и до 7680×7680 px одновременно |
| Документ/файл | 50 000 000 байт | До 4 ГБ |
| Аудиофайл | 50 000 000 байт; требования MAX к длительности сохраняются | До 256 МБ и не более 60 минут одновременно |
| Видеофайл | 50 000 000 байт | До 250 МБ; отдельный предел длительности в разделе загрузки не указан |
| Текст/подпись | Деление на сообщения без намеренного обрезания | До 4000 символов в одном сообщении |

Источник — [официальная загрузка MAX](https://dev.max.ru/docs-api/methods/POST/uploads).
Пределы API для файлов не равны ограничениям кнопки записи голоса/кружка
в конкретном приложении телефона. Круглая форма видеосообщения через Bot API
не гарантируется: отдельного документированного типа `video_note` нет.
Обычный MP4 поддерживается. В одном сообщении API допускает до 12 картинок
или видео; аудио и документы плагин отправляет отдельными сообщениями.
Поднимать предел плагина выше 50 МБ без потокового кеша и повторной приёмки
не следует. Длинная речь на CPU может обрабатываться заметно дольше её
короткого тестового примера.

### Воспроизводимая живая проверка

Используйте Python окружения с установленным настоящим Hermes. Скрипт
`scripts/max_media_acceptance.py` не запускает polling, не передаёт
сообщения модели и не меняет службы либо конфигурацию. По умолчанию он
читает только состояния inbox и обезличенную схему вложений:

```bash
python scripts/max_media_acceptance.py --home "$HERMES_HOME"
```

Для четырёх небольших контрольных вложений требуется явный `--send`,
разрешённый ID владельца, Pillow, ffmpeg/ffprobe и **новый** файл квитанции:

```bash
python scripts/max_media_acceptance.py --home "$HERMES_HOME" \
  --send --owner-id OWNER_ID --receipt /tmp/max-media-check-unique.json
```

Скрипт использует медиаметоды адаптера, читает созданные сообщения через
API, скачивает вложения обратно и проверяет декодирование, байты документов
и настоящий кеш Hermes. Существующая квитанция блокирует повторный запуск.
`--file /path/in/hermes/cache/report.pdf` можно повторить для нескольких
файлов; `--as-documents` отправляет их оригиналами. Произвольные локальные
пути штатная защита Hermes не разрешает. Вывод не содержит токенов, текста
переписки или подписанных URL. Этот тест **не** заменяет входящее сообщение
реального владельца, проверку ответа по содержимому и приёмку на телефоне.

При неудачном входящем скачивании пользователь получает прямое сообщение
по-русски. Если у сообщения без подписи не осталось ни одного читаемого
вложения, оно отмечается как ошибка и не запускает модель с пустым файлом.

### Команды MAX

Плагин регистрирует до 32 команд через `PATCH /me/commands`. Фактический
набор зависит от командного реестра установленной версии Hermes. Если реестр
поддерживает все перечисленные команды, основной набор содержит 18 пунктов:

```text
/menu /commands /help /status /new /stop /model /goal /reasoning /compress
/sessions /resume /retry /undo /agents /whoami /queue /maxstatus
```

Если приложение MAX не показывает системное меню бота, отправьте `/menu`:
плагин вернёт короткий список обычным текстом и добавит кнопки. `/commands`
передаётся Hermes без перехвата; `/commands 2` открывает вторую страницу полного
каталога. `/reasoning` показывает выбор, если установленный Hermes использует
`send_choice_picker`; `/reasoning high` остаётся штатным текстовым вариантом.
Названия команд, аргументы и область действия описаны в
[справочнике команд MAX](max-commands.md).
После перезапуска gateway в журнале должна появиться строка вида
`MAX command menu registered (N): ...`.

Команда `/maxstatus` показывает состояние polling-задачи, время с последнего
успешного ответа, число последовательных ошибок и очередь inbox. Если один
запрос не завершается дольше 120 секунд, состояние отображается как отсутствие
ответа; эта диагностика не включает токены, текст переписки или подписанные URL.

Для проверки регистрации без polling и без запуска модели:

```bash
python scripts/max_commands_live_smoke.py
```

Скрипт выполняет только `GET /me`, `PATCH /me/commands` и повторный `GET /me`;
токен и содержимое переписки он не печатает. Запускать его следует при одном
единственном владельце polling, чтобы не смешивать диагностический вызов с
обработкой событий.

Автоматические проверки выполняются против установленных типов Hermes и
закреплённых ревизий `0.21.4` и `v2026.9.24`. Они не доказывают реальную
доставку медиа на телефон, чтение содержимого моделью, живой групповой callback
или работу CDN без VPN. Эти проверки требуют тестового бота либо согласованного
окна с единственным получателем событий.

## 8. Проверка и откат

```bash
python -m pytest -q
```

Нативная проверка двух независимых MAX-транспортов, `/status`, `/new`, пустого
списка администраторов и изоляции профилей:

```bash
python scripts/max_policy_contract.py --hermes-root /путь/к/установленному/hermes
```

Запускайте её Python-окружением проверяемого Hermes с его установленными
зависимостями. Скрипт использует настоящий `GatewayRunner`, создаёт временный
профиль и запрещает сетевые подключения. Отсутствие Hermes или нарушение
контракта приводят к ошибке. Это проверка обработки, а живой обмен с MAX и
отображение ответа на телефоне принимаются отдельно.

Для live-проверки задайте `MAX_BOT_TOKEN` и `MAX_CA_BUNDLE` только в окружении
процесса и запустите `scripts/max_live_smoke.py` без `--poll-seconds`, если
gateway уже работает. Для исходящей медиа-проверки используйте
`scripts/max_media_live_smoke.py`; для обезличенной диагностики upload-ответа —
`scripts/max_upload_live_inspect.py`. Проверка
`scripts/max_adapter_live_smoke.py` использует временный SQLite и collector
вместо вызова модели Hermes; активный gateway не запускается и не
перезапускается.

Перед рестартом gateway выполните loader smoke-тест на текущей версии Hermes.
Для отката остановите gateway и удалите или перенаправьте только
`~/.hermes/plugins/max`. Файлы Hermes core при установке плагина не меняются.

Перед сменой версии сохраните конфигурацию MAX и согласованную резервную копию
SQLite inbox/marker. Текущая проверка на development-кандидате не означает, что
изменения уже установлены в рабочий Hermes; production переключают только после
приёмки медиа и проверки восстановления базы.
